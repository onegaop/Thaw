# macOS 26 浮动栏首次展开

## 范围与验收

沿公开兼容线定位首开先显示彩色应用图标、随后出现菜单栏图像的问题。隔离验证冷缓存、部分缓存、重复展开、浅深外观、回退与延迟收起。保留原安装和用户配置。

## 证据与决定

- 点击由 `ControlItem.performAction` 切换分区；悬停由 `HIDEventManager.handleShowOnHover` 等待后展开分区。两者到达相同的 `IceBarPanel.show`。
- 面板先尝试按显示器恢复缓存、建立内容视图并置前，之后才异步刷新和重新捕获。默认图标偏好下，缺失截图的项目会先使用应用图标；截图到达后，SwiftUI 重新选择图像。
- 系统日志记录过一次水平栏显示 10 项，约 670 毫秒后启动分区补抓；另一次出现了 9/10 缓存恢复，随后补抓，再次打开为 10/10。日志没有帧像素，不能推断所有图标的实际颜色，也不能从面板日志识别输入方式。
- 每次展开独立跟踪首轮捕获。只有面板使用截图、已有录屏权限且当前项目缺图时才显示现有加载文案。图像到齐立即显示；首轮结束仍缺图时沿用应用图标回退。完成旧任务不影响下一次展开。
- 代价是部分命中时，也会短暂显示加载文案；浮动栏仍立即置前。未增加人为延时、截图循环或偏好写入。

## 验证记录

- macOS 26.7.3、Xcode 27.2 上完整 Debug 测试目标编译通过；在独立 Bundle ID 的命令行测试进程中运行六个相关套件，40 个测试通过。进程没有启动 Thaw 的 AppDelegate。
- 新增的离屏测试使用生产的首轮展示逻辑、图像缓存和图标来源选择，提供合成的彩色应用图标与浅深菜单栏截图，通过 SwiftUI ImageRenderer 比较像素。冷缓存和部分缓存显示相同的加载态；首个完整图标行、捕获完毕后的行与热缓存重复打开的行逐像素相同。另测无权限、主动使用应用图标、截图失败与旧任务完成。
- 原有收起策略、自动收起时间、外观着色、尺寸适配、隔离测试通过。通用 Release 两个架构的最低系统均为 15.0。Release 自检通过 36 种待收起状态，Python 隔离检查 4 项通过。全库严格 lint 与基线同为 11 项，新改动无新增告警。
- 测试运行器首次缺少 bundle identifier，已给予专用测试身份。一项夹具曾假设所有进程都有应用图标，经校对实际来源选择逻辑，测试现明确覆盖无源图标时保留可用截图。

## 现场验收

本轮没有在用户桌面安装、启动或录制候选版。交互验收可在独立测试会话记录首次点击、再次点击和菜单栏空白区域悬停，对照画面与缓存恢复数。如果缓存完整时整行仍从彩色变灰，应检查初始截图本身与后续截图的像素差异；本修复只覆盖缺图回退导致的切换。
